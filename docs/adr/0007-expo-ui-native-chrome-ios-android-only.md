# Drop web as a target and NativeWind + React Native Reusables in favor of @expo/ui native chrome

**Status:** accepted — supersedes the web-as-a-target portion of `docs/adr/0005` and all of `docs/adr/0006`.

`docs/adr/0006` chose NativeWind + React Native Reusables specifically so the app could carry a bespoke, non-native-chrome visual identity (`DESIGN.md`'s warm paper/clay palette, Fraunces + Inter) across iOS, Android, and web from one styling system, and explicitly rejected `@expo/ui` because its native SwiftUI/Jetpack Compose views can't be reached by NativeWind's `className` and require a dev client. We're reversing that: the RNR/NativeWind result doesn't read as native enough, and the priority is now genuine native controls over a fully custom look. We're adopting [`@expo/ui`](https://docs.expo.dev/versions/latest/sdk/ui/) for `components/ui/*` and, as a direct consequence, dropping web as a target platform — `@expo/ui` has no web renderer, and maintaining a second component system just for web isn't worth it for a single-tenant app with no web-specific demand driving it. The app now targets iOS and Android only.

We considered keeping web alive by running RNR/NativeWind on web while `@expo/ui` covers iOS/Android, but rejected it: two parallel component systems for one small app is more ongoing cost than the web target is worth right now. We also considered a partial `@expo/ui` adoption (native controls where it has an equivalent, RNR/NativeWind kept for the rest), but chose full replacement so the app isn't left maintaining both styling paradigms side by side.

**Consequences:**
- **Dev client required.** `@expo/ui` needs a dev client; the app can no longer be tested in plain Expo Go. This was the second reason `docs/adr/0006` rejected `@expo/ui` — it's now an accepted cost.
- **NativeWind, Tailwind, and `@rn-primitives` are removed entirely**, not just unused for new components. `DESIGN.md`'s tokens (colors, spacing, radius, font families) move into a plain `theme.ts` constants module — the "least machinery" alternative `docs/adr/0006` originally considered and passed over.
- **`DESIGN.md`'s tokens are kept, not retired, but only apply where the native APIs allow styling.** Components with no `@expo/ui` equivalent (`Card`, `Tag`, `TagPicker`, and similar bespoke domain components) are hand-rolled with plain React Native styling against `theme.ts`, so the brand palette/type survives even though the interactive controls now use native chrome.
- **Icons are unaffected.** `lucide-react-native` / `components/ui/icon.tsx` stays as-is — this decision is about interactive primitives, not iconography.
- **Web is dropped as a target, not deferred.** `components/web/*`, web-specific `Platform.OS` branches, and web-related config/dependencies are removed. This reverses only the web-as-a-target half of `docs/adr/0005` — its Convex + Clerk decision (accounts, cross-device sync) is unaffected and remains the backend architecture. A future reader of `docs/adr/0005` should read its web-layout consequences as no longer current, but everything else in it as still accurate.
