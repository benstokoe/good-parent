# Allow opt-in, per-item Share via the OS-native share sheet

GoodParent's original premise was that data is never shared with anyone, including co-parents — the whole design rested on being a private space where a parent could be honest without an audience. The imported design, however, included a Share flow: the user explicitly asked for it, wanting to choose what and who to share with. We resolved this by allowing Share only as an explicit, per-item, opt-in action (Parent Milestone, Child Milestone, Affirmation) that hands off to the OS-native share sheet — no in-app recipient roster, no continuous or automatic sharing, nothing stored about who a milestone was shared with.

We considered building an in-app "shared with" list (named recipients, possibly via a synced backend) to match the design's dialog more literally. We rejected it: it would mean standing user-to-user infrastructure and a second data-sync mode, for a feature the user only wanted as an occasional, deliberate act ("you choose what and who," each time). A future reader might wonder why an app built around "never shared" has a Share button at all — the answer is that it's a considered, narrow exception (three item types only, explicitly excluding Burn, Journal, and Check-In, which stay private), not a reversal of the app's privacy posture.

**Expo note:** the SwiftUI version hands off to the OS share sheet via `UIActivityViewController`/`NSSharingService`; the equivalent here is `expo-sharing` (or `react-native-share` for finer control) — no in-app recipient roster on this platform either. This decision originated on the SwiftUI version of GoodParent (`../GoodParent`) but the privacy reasoning carries over unchanged.
